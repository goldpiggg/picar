# 추가 기능과 의도 요약

Adeept PiCar 제조사 코드 위에 추가한 기능을 정리했습니다. 목표는 **QR로 방향을 정하고, 상자 앞 30cm까지 다가가 멈춘 뒤, PICK/PLACE QR로 물체 배치를 확인하고 로봇팔로 두 물체를 반대쪽 빈 박스로 옮기기**입니다.

## 1. QR 인식과 방향 결정
| 기능 | 의도 |
|---|---|
| `qr_scan.py`, 기존 WebServer에 QR 연동 | 제조사 서버와 웹 제어를 그대로 쓰면서, 카메라로 QR을 읽어 LEFT/RIGHT 방향을 정하기 위해 |
| QR 1회 인식으로 단순화, 시작 조건 완화 | 여러 번 확인하느라 출발이 늦거나 멈추는 문제를 줄이기 위해 |

## 2. 초음파 접근과 정지
| 기능 | 의도 |
|---|---|
| 초음파 거리로 접근 후 정지 | QR 방향이 정해지면 사람이 조작하지 않아도 상자 앞까지 가기 위해 |
| 배터리 전압 보정 주행(5V 기준 PWM) | 배터리 잔량에 따라 속도가 달라져 정지 위치가 바뀌는 문제를 막기 위해 |
| 38cm부터 짧은 펄스로 30cm ±1cm 맞추기 | 관성으로 지나치지 않고 팔이 닿는 정확한 거리에 서기 위해 |
| 초음파 3회 중앙값으로 판단 | 잘못 튄 측정값 하나 때문에 너무 일찍 멈추는 문제를 막기 위해 |
| 정지 후 바퀴·조향 잠금 | 팔이 일하는 동안 차체가 움직이지 않게 하기 위해 |
| 조향 예압과 자이로(MPU6050) 직진 유지 | 조향 유격 때문에 한쪽으로 휘는 것을 줄이기 위해 |

## 3. 로봇팔 자세 가르치기 (`/poses/legacy` 페이지)
| 기능 | 의도 |
|---|---|
| **저장** 버튼 | 웹으로 팔을 맞춘 뒤 그 각도를 `arm_poses.json`에 바로 기록하기 위해(직접 숫자를 적지 않아도 됨) |
| **이동** 버튼 | 저장한 자세를 다시 불러와 맞는지 확인하기 위해 |
| **RIGHT/LEFT 순서 실행**(방향 2 × 배치 2) | 주행 없이 그 자리에서 19단계 전체를 배치별로 미리 시험하기 위해 |
| 카메라 배치 판단 표시 | 정지 위치에서 카메라가 박스 배치를 바르게 읽는지 가르칠 때 바로 확인하기 위해 |
| **팔 이동 정지** | 시험 중 위험하면 바로 멈추기 위해 |
| 저장 시 파일 소유자 유지 | 서버가 root로 돌아도 사용자가 파일을 고칠 수 있게 하기 위해 |
| 동작 기록기(`/record`) | 팔 각도·거리·QR 정보를 CSV로 남겨 나중에 분석하기 위해 |

## 4. 자동 팔 동작

현재 실행 범위는 [팔 초기화·BASE 좌우 90° 회전·QR 시퀀스 선택 표시](QR_PREPARATION.md)까지입니다. 아래 전체 배치 판별과 운반 계획은 보관돼 있지만 웹 미션에서는 자동 운반하지 않습니다.
| 기능 | 의도 |
|---|---|
| 박스 4개(왼쪽 위·아래, 오른쪽 위·아래)마다 자세 | 물체 위치가 대각선 두 배치 중 랜덤이라, 어느 박스든 집고 놓을 수 있게 하기 위해 |
| PICK/PLACE QR로 배치 판단(`LAYOUT_WAIT`) | 정지 후 팔을 움직이기 전에 물체가 어느 대각선에 있는지 카메라로 정하기 위해. 스펀지가 PICK QR을 가려도 PLACE QR로 판단 |
| 판단 못 하면 팔 정지 | 잘못된 박스로 팔을 내리지 않게, 5초 안에 확정 못 하면 `ERROR`로 끝내기 위해 |
| 19단계 자동 순서 | 각 물체를 같은 줄의 반대쪽 빈 박스로 옮기기 위해. QR 방향 쪽 물체가 먼저 |
| `arm_enabled`, `calibration_confirmed` 안전장치 | 자세를 다 확인하기 전에는 팔이 자동으로 움직이지 않게 하기 위해 |

예: LEFT QR, 물체가 왼쪽 위·오른쪽 아래(`LEFT_TOP`): 중앙 → 왼쪽 위 물체 집기 → 중앙 운반 → 오른쪽 위 박스에 놓기 → 오른쪽 아래 물체 집기 → 중앙 운반 → 왼쪽 아래 박스에 놓기.

## 5. 팔 움직임 품질
| 기능 | 의도 |
|---|---|
| PCA9685 초기화를 한 번만 | 명령마다 PWM이 잠깐 끊겨 팔이 처지던 문제를 없애기 위해 |
| 전원 리셋 감지 후 각도 복구 | 전압이 떨어져 칩이 리셋돼도 팔이 늘어지지 않게 하기 위해 |
| 수동 조작 속도 일정하게 | 한 번에 크게 움직이지 않게 하기 위해 |
| 부드러운 곡선 이동(최소 저크) | 출발·정지 때 덜컹거려 물체를 떨어뜨리는 문제를 막기 위해 |
| 물체를 든 동안 느린 운반 속도 | 운반 중 흔들림을 줄이기 위해 |
| 집게 꽉 쥐기(접촉 후 더 조이기) | 스펀지처럼 눌리는 물체도 놓치지 않게 하기 위해 |
| 조작 속도 `arm_jog_speed` 설정 | 코드를 고치지 않고 `mission_config.json`에서 속도를 바꾸기 위해 |
| 관절 범위 0~189°(펄스 500~2500µs) | MG996R 서보가 낼 수 있는 범위를 더 쓰기 위해. 저장한 각도는 그대로 |

## 6. 되돌린 변경
| 변경 | 이유 |
|---|---|
| 직진 속도 감속·개인 설정 | 원래 동작으로 되돌림 |
| 시작할 때 팔을 천천히 초기 자세로 | 사용자 요청으로 원래 시작 동작으로 되돌림 |

## 사용 순서 요약
1. `mission_config.json`에서 `auto_approach_enabled`, `arm_enabled`를 `false`로 두고 서버를 실행합니다.
2. `http://로봇IP:5000/poses/legacy`에서 자세를 맞추고 **저장**합니다.
3. 카메라 배치 판단이 맞는지 보고, **RIGHT/LEFT 순서 실행**(배치 2가지 모두)으로 미리 시험합니다.
4. 문제없으면 `calibration_confirmed`, `arm_enabled`, `auto_approach_enabled`를 `true`로 바꾸고 서버를 재시작합니다.

자세한 내용은 [ARM_CALIBRATION.md](ARM_CALIBRATION.md)와 [README.md](../README.md)를 참고하세요.
