# 제조사 코드 출처 및 변경 기록

- 원본 저장소: https://github.com/adeept/Adeept_PiCar-Pro
- 기준 커밋: `7703206c5e9e345c772232c0686e381790b87bb0`
- 기존 사용자 이력은 그대로 유지하고 원본 기준 커밋의 파일 구성을 가져옵니다. 제조사 과거 커밋에는 API 키가 포함되어 GitHub Push Protection에서 차단되었으므로 제조사 이력은 병합하지 않습니다.
- 원본 106개 파일 전체를 포함합니다. 공식 웹 화면의 이미지·글꼴·번들 JS, Client, Examples, setup.py를 생략하지 않았습니다. 원본에 이미 추적된 pyc 파일도 원본 구성에 포함되어 있습니다.
- 원본 README는 `docs/ADEEPT_README.md`에 원문 보관하고 루트 README에도 원본 소개·저작권 부분을 남겼습니다. 별도 라이선스 부여나 제조사 공식 인증을 주장하지 않습니다.

## 원본에서 수정한 파일

1. `Server/WebServer.py`: 기존 실행점을 유지하면서 공용 QR runtime 시작 및 종료 처리 추가. 새 main.py 없음.
2. `Server/app.py`: 기존 화면·영상 유지. `/mission`과 읽기 전용 `/mission/status` 추가.
3. `Server/camera_opencv.py`: 공유 원본 프레임을 QR runtime에 전달. 수업의 USB 웹캠을 기본으로 지원하고 설정으로 원본 CSI 방식 선택. Picamera2는 CSI 선택 시에만 import. 카메라 해제 및 오류 전달 추가.
4. `Server/base_camera.py`: 첫 프레임은 15초, 이후 프레임은 5초의 별도 대기 시간을 적용. 초기 캡처 오류도 바로 호출자에게 전달하고 무한 대기를 방지.
5. `README.md`: 통합 설치·실행·모듈 연결 안내 추가. 원본 README 원문은 별도 보존.
6. `Examples/14_Example_Of_AI/TalkToAI.py`: 원본에 포함된 API 키를 제거하고 `DEEPSEEK_API_KEY` 환경변수에서 읽도록 수정. 이 AI 예제는 QR 실행 경로에 포함되지 않으며 QR 기능에는 API 키가 필요하지 않습니다.

모터 `Move.py`, 서보 `RPIservo.py`, 기존 `Functions.py`의 주행 알고리즘은 변경하지 않았습니다. `Ultra.py`는 실제 echo 획득 지점의 번호·시각·실패 상태를 제공하도록 수정하고 `checkdist()` API는 유지합니다. 내부 큐 길이는 1로 두어 사용자 측 중앙값 필터와 중복 지연을 줄입니다.

## 추가 모듈

- `Server/mission_bridge.py`: 기존 Server와 사용자 패키지 연결. 저장소 루트 경로를 파일 위치 기준으로 구하므로 실행 디렉터리에 의존하지 않습니다.
- `picar_mission/config.py`, `mission_config.json`: 기본 36cm(이전 30cm)·보정 0·USB 카메라 설정.
- `picar_mission/runtime.py`: 최신 프레임 큐, 연속 인식, 확정 방향 저장. 모터/서보 import 없음.
- `picar_mission/status.html`: 상태 확인 화면.
- `scripts/register_service.py`: 이미 설치된 서비스의 실행 경로를 이 체크아웃으로 옮기는 선택 도구. 실행해야만 시스템 서비스가 변경됩니다.
- `tests/`: 실물 QR 이미지와 가상 장치 통합 테스트. 이미지 출처는 수업에서 제공된 QR.zip입니다.

## 이전 정밀 접근 코드의 동작과 한계

기존 웹 제어 화면은 유지합니다. 기본 자동 모드에서는 QR 인식 후 초음파 기반 직진·감속·30cm 정지 및 안정 확인까지 실행하고 `STOPPED_WAIT`에서 대기합니다. 팔 시퀀스는 구현되어 있으나 임시 자세값이므로 `arm_enabled=false`, `calibration_confirmed=false`로 자동 실행을 차단했습니다. 실제 자세 보정 후 활성화하면 정지 확인에서 팔 작업과 완료 상태까지 이어집니다. 기존 웹/음성/영상 자동 기능과 서보 설정 명령은 자동 모드에서 차단하여 충돌을 방지합니다. 정지 명령은 주행과 팔 작업을 모두 취소하며, QR 대기 중 버튼 해제 신호에만 아래의 예외를 적용합니다. 설정의 `auto_approach_enabled=false`로 기존 수동 제어를 선택할 수 있습니다. 제조사 프로그램 시작 시의 기존 서보 초기화는 유지됩니다.

`arm_poses.json`에 예시 각도와 속도·대기 시간을 모았고 `arm_sequence.py`에서 보정 확인·각도 범위·명령 변경 속도·시간초과를 검사합니다. `ArmAdapter`는 기존 서보 객체의 채널 1~4에 절대 목표각을 전달합니다. 상태 API의 `commanded_servo_angles_deg`는 수동 보정 시 기록할 수 있는 메모리상의 명령값이며 실제 위치 센서의 측정값이 아닙니다. 예시 값과 측정 항목은 `docs/ARM_CALIBRATION.md`에 있습니다.

추가된 `mission_controller.py`, `distance.py`, `approach.py`는 제조사 모터와 조향 객체를 재사용합니다. 웹 소켓 연결마다 모터 객체를 다시 초기화하지 않도록 자동 모드의 초기화 경로를 제한했습니다. SIGINT/SIGTERM과 서버 종료에서 모터 정지·미션 종료를 요청합니다. HTTP `/mission/stop`은 중지 전용이며 원격 재출발 API는 없습니다.

공식 setup.py는 설치·네트워크·자동 실행·재부팅을 포함하는 원본 그대로입니다. 기존 설치 환경에서 서비스 경로만 변경할 때는 register_service.py를 사용합니다. 서비스 등록 도구는 이 작업 중 PC에서 실행하지 않았고, 실제 로봇에서도 아직 실행하지 않았습니다.

## 이전 출발 조건 완화 이력

- QR 기본 조건은 연속 2프레임·0.15초, 관측 간격 및 처리 프레임 나이 한도는 1.5초입니다. LEFT/RIGHT 동시 인식·PICK/PLACE만 인식한 경우에는 출발하지 않습니다.
- 차체가 움직이기 전에는 초음파 실패를 최대 5초 동안 재시도합니다. 정상 새 측정값 3개가 있어야 출발하며, 주행 중 센서 오류와 0.25초 나이 제한은 유지합니다. 주행 최대 시간은 40초, 진행 확인은 5초 동안 0.3cm입니다.
- QR 방향을 저장한 뒤 카메라 오류·영상 중단으로 초음파 기반 주행이나 고정 자세 팔 순서를 취소하지 않습니다. 물체 추적 기능을 추가한 변경은 아닙니다.
- QR 대기 중 차단된 수동 버튼의 해제 신호만으로 자동 미션을 취소하지 않습니다. 명시적 stop 및 HTTP 전체 중지는 계속 취소하며 QR 확정 후의 버튼 해제도 취소로 처리합니다.
- 30cm 목표·정지 허용 범위·팔 임시 각도 잠금은 유지했습니다. 이 변경에는 중단해 둔 카메라 초기화 수정이 포함되지 않습니다.

## 현재 기본 동작: QR → 직진 → 36cm 정지

현재 `Server/mission_bridge.py`는 `DirectMissionController`를 생성합니다. 위의 정밀 접근·조건 완화 코드는 이전 동작으로 보관합니다.

- QR 프로젝트 기본값은 1프레임·0초입니다. 중복·방향 충돌·PICK/PLACE만 있는 경우는 계속 출발시키지 않습니다.
- 정상 현재 거리값 하나가 36cm보다 크면 직진 PWM 40을 명령합니다. 출발 전 세 번 측정·중앙값 준비·급변 판정·카메라 재확인·조향 대기·진행량 판정은 직접 주행 경로에서 사용하지 않습니다.
- 감속 없이 일정 출력을 유지하고 현재 초음파가 36cm 이하이면 즉시 정지 명령 후 대기합니다. 기본 `approach_complete`는 거리 기준 도달과 정지 명령을 뜻하며, 실제 정지 위치나 차체 정지를 확인한 결과가 아닙니다.
- 정지선 도달 전 거리 누락·비정상 거리·0.5초 초과의 오래된 거리는 멈춘 채 최대 3초 동안 다시 읽습니다. 40초의 주행 시간 한도와 사용자 중지는 유지합니다. `drive_command`와 `drive_error` 로그로 전진 명령 전송 여부와 중지 이유를 확인할 수 있습니다.
- 팔 비활성 기본값은 유지합니다. 팔이 명시적으로 활성화되고 자세 보정까지 확인된 경우에만 정지 명령 후 1초 대기·팔 순서로 연결합니다. 정지 후 거리 검사는 하지 않습니다.

정지 기준은 사용자 요청에 따라 36cm로 변경했습니다. 기본 설정 파일과 설정 파일이 없을 때의 기본값을 함께 변경했으며, 주행 출력 40과 QR 1회 조건은 유지했습니다.

## 정지선 도달 후 바퀴 잠금과 조건 정리

- 36cm 이하의 첫 측정에서 `target_stop_latched=true`를 기록합니다. 이 미션에서는 잠금을 풀지 않으며 DriveAdapter도 이후 전진·조향 명령을 거부합니다. 팔 동작과 완료 이후에도 잠금을 유지합니다.
- 기본 팔 비활성 상태는 바로 대기합니다. 보정된 팔을 활성화했다면 `ARM_WAIT`에서 1초 대기 후 시작합니다. 기존 거리 ±1cm·서로 다른 측정 4개·0.6초 안정 확인을 재사용하지 않습니다. 대기 시간은 실측 전 임시값입니다.
- 정지선 도달 후에는 초음파·QR을 다시 읽지 않습니다. 주행 중 측정 일시 실패의 정지·재시도는 정지선 도달 전으로 제한합니다.
- 팔이 꺼져 있으면 자세 파일을 로드하지 않습니다. 수동 각도 조회와 중지는 팔 활성화 여부와 별개로 유지합니다.
- 현재 사용하는 설정만 기본 JSON에 남기고 사용하지 않는 감속·정밀 접근 설정의 검사를 제거했습니다. 기존 정밀 모드 코드는 참고 및 회귀 테스트를 위해 보관합니다.
- 이전에 보류했던 카메라 시작 대기 처리는 이번 요청에 따라 반영했습니다. 첫 프레임 15초와 일반 프레임 5초를 분리하고 즉시 발생한 초기화 오류를 놓치지 않도록 했습니다. 카메라 장치를 여는 백엔드는 변경하지 않았습니다.
