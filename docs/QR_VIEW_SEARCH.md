# 두 박스 사이 보기와 짧은 QR 탐색

QR 하단이 잘리던 시야를 보정하기 위해 준비 자세의 `qr_prepare_elbow_offset_deg` 기본값을 -20°에서 -30°로 조정했습니다. 초기 팔꿈치가 90°면 QR 준비 목표는 기존 70° 대신 60°입니다. LEFT/RIGHT 모두 적용되며 BASE와 동시에 이동하므로 별도의 대기 단계는 추가하지 않습니다. 탐색 시 이 내림을 반복 적용하지 않고, 저장된 집기·놓기 자세 및 집게 각도는 바꾸지 않습니다. 실제 화면에서 QR 전체와 아래 여백이 들어오는지는 현장에서 확인해야 합니다.

QR 준비 각도는 저장된 같은 쪽 A/B 접근 자세의 BASE 평균을 사용합니다. 현재 저장값은 LEFT 164.5°, RIGHT 6.5°입니다. 접근 자세가 빠져 있으면 `qr_prepare_left_base_deg=165`, `qr_prepare_right_base_deg=7`을 사용합니다. 집기·놓기 각도와 집게 힘 관련 설정은 바꾸지 않습니다.

처음 위치에서 판별되면 추가 탐색 없이 즉시 기존 운반 순서로 넘어갑니다. 첫 위치 도착 후 약 0.55초까지 결과가 없으면 BASE만 중심보다 -10°, +10°인 위치를 짧게 확인합니다. 관절 범위를 넘는 목표는 경계로 제한합니다. 팔꿈치 기울기는 탐색 때 반복 적용하지 않습니다.

추가 각도 탐색은 첫 위치 도착 후 `qr_scan_timeout_seconds`(기본 1.5초)로 제한합니다. 이후에는 새 탐색을 시작하지 않고 마지막 시야에서 최대 0.6초 더 판독 결과를 기다립니다. 그때도 결과가 없으면 `QR_VIEW_NOT_FOUND: QR 시야 확보 실패`로 정지합니다. 인식 결과는 모든 탐색 상태에서 시간 초과보다 먼저 처리하므로, 같은 제어 주기에 확인된 결과를 버리지 않습니다. 초기 회전 시간은 이 추가 탐색 예산과 별개입니다. 판별되면 추가 대기 없이 다음 제어 주기에 운반으로 전환합니다.

거리 보정의 자동 후진은 기본적으로 꺼져 있습니다(`reverse_correction_enabled=false`). 목표 허용범위보다 가까워지면 `TARGET_OVERSHOOT`로 정지하고 새 미션 전까지 재주행하지 않습니다. 짧은 보정 주행은 제어 루프와 별도의 타이머도 정지를 요청합니다. 모터 하나의 정지 쓰기가 실패해도 나머지 모터에 정지를 시도합니다. I2C 통신 자체가 멈추거나 하드웨어가 명령을 받지 못하는 경우까지 소프트웨어 타이머가 정지를 보장하지는 않습니다.

PICK과 PLACE 두 개를 읽거나, 하나를 읽고 별도의 다른 QR 외곽을 정확히 한 개 찾으면 좌우 순서를 비교합니다. QR 한 개가 화면 중앙의 어느 쪽에 있다는 이유만으로 A/B를 정하던 조건은 제거했습니다. 카메라가 비스듬히 향하면 PICK이 화면 오른쪽에 보여도 실제로 PLACE 왼쪽일 수 있기 때문입니다.

같은 방향의 짧은 탐색은 A/B 좌우 순서를 바꾸지 않으므로 대기 프레임과 진행 중인 판독을 유지합니다. 프레임 판독 시작 당시 정지 시야였는지도 유지합니다. 전체 중지·카메라 오류·새 미션의 결과 무효화는 그대로 적용됩니다.

`sudo apt-get install -y python3-zxing-cpp`로 설치한 ZXing을 PICK/PLACE의 첫 판독기로 사용합니다. 두 개를 읽으면 즉시 결정하며, 하나를 읽으면 다른 QR 외곽과 비교합니다. 불충분하면 OpenCV 판독 결과를 결합합니다. `/mission/status`의 `qr.decoder_backend`로 사용 중인 판독기를 확인할 수 있습니다. 설치되지 않았거나 판독기 오류가 나면 기존 OpenCV 경로를 사용합니다. 시작 LEFT/RIGHT 판독은 기존 다중 인식 경로를 유지합니다.

전체 중지는 탐색을 멈추고 현재 자세를 유지합니다. 검증은 가상 드라이버와 저장 촬영 이미지로 수행했으며 실제 시야·전체 13초대 기록은 현장에서 확인해야 합니다.
